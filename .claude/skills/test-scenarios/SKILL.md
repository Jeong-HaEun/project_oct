# 시험 문제 짜기 (TDD 1단계)

인자: 이슈 번호 (예: `1`). 없으면 사용자에게 묻는다.

## 순서

1. **읽기**
   - `gh issue view <번호>` 로 이슈 본문과 완료 체크리스트를 읽는다.
   - 이슈가 가리키는 근거 문서를 읽는다: `docs/specs/summary-page/prd.md`, `spec-fixed.md`, `docs/metrics.md`, `docs/api.md`.
   - `src/utils/` 에 이미 있는 함수를 확인한다. 같은 일을 하는 함수가 있으면 새로 만들지 않고 그걸 쓴다.
2. **함수 모양 제안** (표)
   - 칸: 파일 · 함수 이름 · 받는 값 · 돌려주는 값 · 한 줄 설명
   - 계산은 `src/utils/` 의 순수 함수로 둔다 (같은 값을 넣으면 항상 같은 값이 나오고, 화면·서버를 건드리지 않는 함수). 서버 호출은 `src/api/`.
   - 계산 불가(분모 0, 비교할 데이터 없음)는 `null` 로 돌려주고, `-` 로 바꾸는 일은 표시용 함수가 한다.
   - 날짜는 `"YYYY-MM-DD"` 문자열로 주고받는다. "오늘"이 필요한 함수는 오늘 날짜를 **인자로 받는다** (테스트에서 날짜를 고정하기 위해서).
3. **시나리오 표** — 함수마다 [정상] [경계] [예외] 로 나눈다.
   - 칸: ID(`S1`, `S2` …) · 분류 · 상황 · 넣는 값 · 기대 결과
   - ⚠️ **경계값은 "최대 −1 / 최대 / 최대 +1" 세 개를 꼭 넣는다.** 예: 6일 / 7일 / 8일치 데이터, 분모 0 / 1.
   - 기대 결과는 구체적인 숫자로 쓴다 ("올바른 값" 금지).
4. **대조표** — 이슈 체크리스트 한 줄마다 검사하는 시나리오 ID 를 적는다.
   - 칸: 체크리스트 줄 · 시나리오 ID · 검사 방법
   - 검사 방법은 `자동(node --test)` 또는 `화면 확인(브라우저에서 눈으로)`. 로딩 문구·버튼처럼 화면에서만 보이는 줄은 화면 확인이다.
   - 시나리오가 없는 체크리스트 줄이 있으면 안 된다. 체크리스트에 없는 시나리오도 만들지 않는다 (YAGNI).
5. ⏸ **멈추고 승인받는다.** 함수 모양과 대조표를 보여주고 "이대로 저장할까요?" 를 묻는다.
6. 승인되면 `docs/specs/summary-page/issues/issue-<번호>-tests.md` 에 함수 모양 · 시나리오 · 대조표를 저장한다. 다음 단계 `/tdd-red <번호>` 가 이 파일을 읽는다.

## 지키는 것

- 이 단계에서는 **코드를 쓰지 않는다.** 문서만 만든다.
- 설명은 쉬운 한국어로, 새 용어는 한 줄로 풀어 쓴다.
