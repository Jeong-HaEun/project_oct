# Green — 통과시키기 (TDD 3단계)

인자: 이슈 번호 (예: `1`). 없으면 사용자에게 묻는다.

## 순서

1. **준비**
   - `docs/specs/summary-page/issues/issue-<번호>-tests.md` 와 해당 `*.test.js` 를 읽는다.
   - `node --test` 로 지금 실패 목록을 보여준다. 고친 파일 목록을 알려주고 승인받은 뒤 시작한다.
2. **하나씩 통과시키기** (테스트 하나마다 반복)
   1. 실패한 테스트 하나를 고른다.
   2. 그 테스트를 통과할 **최소한의 코드**만 쓴다.
   3. `node --test` 를 돌려 "통과 N / 남은 실패 M" 을 한 줄로 알린다.
   4. 앞에서 통과하던 테스트가 깨졌으면 바로 고친다.
3. ⛔ **멈추는 규칙 (사람 개입점)**
   - **같은 테스트가 5번 실패하면 멈추고 보고한다.** 시도한 것, 실패 메시지, "테스트가 틀렸을 가능성" 을 적고 사용자와 함께 본다.
   - **테스트를 고쳐서 통과시키지 않는다.** 테스트가 틀린 것 같으면 멈추고 묻는다.
   - **테스트에 없는 기능은 넣지 않는다** (YAGNI: "그거 안 쓸걸?").
4. **"남은 실패: 0"** 을 보여준다.
5. **화면 연결** — 대조표에서 "화면 확인" 인 줄만 대상.
   - 만들 컴포넌트 목록을 알려주고 승인받는다.
   - 먼저 `design-rules` 스킬을 따른다.
   - 컴포넌트는 `src/utils/` 함수를 부르기만 한다 (계산을 컴포넌트에 쓰지 않음). 서버 호출은 `src/api/` 에만.
   - 사용자에게 `npm run dev` 로 화면 확인 줄을 하나씩 확인하는 방법을 번호로 안내한다.
6. **마무리 확인**: `node --test`, `npm run lint`, `npm run build` 가 모두 통과하는지 보여준다.
7. 커밋할지 묻는다. 메시지 예: `feat(summary): 합계 카드 4개 추가 (#<번호>)`.
   - 다음은 Refactor: 사용자가 "테스트는 그대로 두고 코드만 정리해줘" 라고 하면, 테스트 파일은 건드리지 않고 코드만 정리한 뒤 테스트가 여전히 다 통과하는지 보여준다.
